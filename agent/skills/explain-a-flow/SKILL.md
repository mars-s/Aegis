# Explain a flow

- A **diagram**: one node per step or part, short names ("01 · Brief"), a note of a few words each. kind step for process steps, service, store, queue, model and so on for systems. Edges in the order work flows; label only the edges where something changes (approved, retries, events). Loops back are fine; the app draws them dashed.
- direction right for a short pipeline of up to six steps, down for anything taller or branching. Use layers when the nodes fall into clear bands (client, server, data).
- A **reply** above it: the flow in one sentence and the one step that matters most.
- A **list** beside it only for things the diagram cannot show (risks, open questions).
